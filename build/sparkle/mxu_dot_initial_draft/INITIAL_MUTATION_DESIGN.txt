Finding: native initialization changes alone are not semantic counterexamples
OpenTPU/MxuDot.lean's IMPL2 loop creates wd0 with:
  clocked "wd0" 16 (ref "en_c") <decoded low/high weight expression>
OpenTPU/Circuit.lean::clocked emits:
  .register "wd0" "clk" ("no_reset", .synchronous)
    (mux (ref "en_c") value (ref "wd0")) 0
MxuPhysical.dot retains wd0; only actual DSP-replaced register names are removed.
The corresponding original storage is g_sys.wd[0], declared in the packed
logic [D-1:0][15:0] wd vector and updated on en_c. It has no initial constraint.
The physical-dot reference preserves that declaration/update. The original
local otpu_skew and otpu_delay pipeline registers also have no initial clauses.

The source initial hi_v=0 is a simulation diagnostic under `ifndef SYNTHESIS
and is removed by this exact synthesized reference scope. fd_rst=0 belongs to
outer controller/FIFO diagnostics, outside the extracted dot region. Neither
can justify a local-parent native initializer counterexample. DSP primitive
initializers belong to the separate concrete helper premises, not local state.
Text inspection found no reference-defined local parent register initializers;
the real init-preserving extraction must confirm this rather than assuming it.

Therefore compiled native wd0 initial0->1 should generally STILL admit a valid
reference witness with g_sys.wd[0]=1. It is a useful source-applicability/witness-
change guard (and optionally a positive witness-adaptation test), not a failed
refinement theorem. Do not require its rejection as a semantic counterexample
and do not replace arbitrary reference initial state with a fabricated zero.
